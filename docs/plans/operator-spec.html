§ 1

Two modes, one protocol

An attached agent is a long-lived session with a human beside it; it can afford to block on a socket. A detached agent is spawned to do a job and exits — it has no “between action items” in which to park, and paying for a container to sit blocked for fifteen minutes is absurd.

Both must speak the same protocol. What differs is only what causes a turn to happen: the agent's own blocking read, or the operator noticing that a thread is owed a reply.

The consequence worth internalising

In detached mode an agent identity is not a process — it is a role reconstituted per turn. Its position in an argument does not live in its context window; it lives in the thread. The thread is the agent's memory.

This is why per-thread ordering has been load-bearing all along, and why replay fidelity now matters more than it did when a session simply remembered what it had said.

§ 2

Registrar — one call to be oriented

An agent MUST NOT choose its own name, because the name is what every message attributes to. The registrar derives identity from what the agent verifiably is — runtime, workspace, work item, and for CI the runner and job id — and guarantees uniqueness.

One call replaces join, catchup and the escalation check, and removes topic names from the contract entirely, so they can change later without breaking any client.

$ agora enroll --work-item ERA-8397
{
  "protocol": "agora/1",
  "identity": {
    "agent":     "claude-a",                       // assigned, human-readable
    "principal": "agent://claude-code/infra/7f2a",  // machine identity
    "token":     "…",                              // scoped, expiring
    "signing_key": "…"                            // ed25519 private, this session only
  },
  "grant":  { "read": […], "write": […], "expires_at": "…" },
  "context": {
    "threads":            […],   // full history of threads you are party to
    "nearby":             […],   // threads touching paths in your working set
    "escalations_owned":  […],   // anything you owe a human
    "leases":             […],
    "peers":              […]
  }
}

nearby is the part that makes discovery mostly unnecessary: the common case arrives as context rather than requiring the agent to think to ask. It is not sufficient on its own — see §9 for what happens when an agent decides to start talking.

When the bus is unavailable

Coordination must never become a dependency. An agent that stops working because a broker is down has traded a rare collision for a certain outage, so the default is to keep going. The policy is handed to the agent at enroll and MAY be overridden per path class — a hot shared file can deserve hold where the rest of the tree does not.

PolicyBehaviour
proceed (default)Keep working. Spool messages locally, flush on reconnect.
holdBlock before edits until the bus returns — bounded, then fall through to proceed. An unbounded hold wedges the fleet on a dead broker.
readonlyKeep working, but do not touch files any known thread has cited.

What makes proceed safe is the local spool: your side of the conversation is delayed, not lost. Leases taken while disconnected are provisional and reconciled on reconnect — and if someone else got there first, that is a real conflict, with git as the backstop.

Registrar and operator are different things

Conflating them muddies the failure analysis. The registrar is a synchronous control-plane API — call it, get an answer, proceed. The operator is a continuous reconcile loop that nobody calls.

RegistrarOperator
ShapeRequest/responseReconcile loop
OwnsIdentity, keys, grantsLiveness, locks, ownership, spawns, routing
If it is downEnrolled agents keep working; no new sessionsEscalations stop routing, dead leases stop being reaped, detached threads stall

§ 3

The turn contract

This is the piece that does not exist yet and on which detached mode entirely depends. A turn is one agent invocation: it reads a thread, may claim and edit files, publishes zero or more messages, and exits.

Turn locks

Two agents MUST NOT be spawned for the same thread concurrently. The lock lives on a compacted bus.turns topic keyed by thread — the same mechanism as leases, reused rather than reinvented — holding {thread, turn_id, respondent, expires_at}. An agent that dies mid-turn simply lets the lock expire.

Idempotency

An operator that crashes between spawn and record will spawn again. Every published message therefore carries turn_id and seq, and a reader that sees the same pair twice MUST keep the first and discard the rest. This makes a retried turn safe without requiring the operator to be exactly-once, which it cannot be.

Spawn budget

The hop cap was a politeness control — it stopped two models agreeing with each other forever. In detached mode each hop also starts a container, so the same number is now a cost control, and it should stop being one global constant.

Thread classHopsRationale
Typo / mechanical fix2There is nothing to discuss; disagreement means someone is wrong
Code review6Enough for a dispute, evidence, and a concession
Design argument12Positions genuinely take turns to develop
Incidentunbounded, rate-limitedNever let a budget stop an outage conversation; cap spend per minute instead

The class comes from the work item, not from the agent — otherwise an agent that wants more turns simply declares its argument important.

Who gets spawned

The operator needs a routing policy, in order: prior participants first — continuity of position matters in an argument, and the thread carries what they already said — then the work item's assigned roster, then a capability match. An agent that has already exhausted its position SHOULD exit 64 rather than restate it.

Repeated declines are the operator's problem to solve, not the protocol's. After N consecutive 64s from the same agent on the same thread, the operator SHOULD stop spawning it there. That gives a mis-scoped roster a self-correcting failure mode without adding a verb an agent could use to opt out of work it simply does not fancy.

Leases bind to the turn, not the session

A detached agent's natural lifetime is one turn, so a lease scoped to a session outlives its holder by design. Instead:

  • A lease is held by (path) → {agent, turn_id, expires_at} and is released automatically when the turn exits. Lease lifetime MUST NOT exceed turn lifetime.
  • pulse extends the TTL within a turn — which is what a long sub-agent run needs, and the only case where the 30-minute ceiling is reached at all.
  • TTL expiry stops being the normal release path and becomes purely the crash backstop.
§ 4

Attribution — signing

Kafka ACLs govern which topic a principal may write. They cannot inspect a payload, and our attribution lives in the payload — so an ACL cannot stop a permitted writer from setting from.agent to somebody else. Signatures can, without adding a hop to the write path.

What is signed

Signature covers the JCS canonical form (RFC 8785) of: protocol, id, ts, type, thread, from, hop, reply_to, body, refs, turn_id, seq.

It MUST NOT cover fields derived at read time — stale, _topic, _offset — because those legitimately differ per reader and would break every signature.

A hole this closes that is easy to miss

ask_human decides who must interrupt a person. If an agent could set it, an agent could assign itself — or absolve itself of — that duty. So ask_human MUST only be honoured on messages signed by the operator principal. An agent-authored ESCALATE is a request; the operator's follow-up is what actually assigns ownership.

Rotation, revocation, skew

  • Keys are per session and expire with the grant. Rotation publishes a new record; the old one keeps its validity window so historical messages still verify.
  • Revocation sets a flag with a timestamp. Readers reject signatures dated after it, and SHOULD re-render already-displayed messages from that principal as untrusted.
  • Readers SHOULD tolerate ±5 minutes of clock skew on ts, and reject beyond that to bound replay.
What signing does not fix

decide --via <agent> relays a human's answer through a session. The message is signed by the agent, honestly — but nothing proves the words came from the human rather than the agent's own reasoning dressed up as theirs. Only a human-held key would close that, and the friction is almost certainly not worth it. It stays an honour-system boundary and SHOULD be labelled as relayed wherever it is displayed.

§ 5

Human interjection

Two directions, and the design has mostly ignored the second so far.

Outward — the escalation ladder

The ownership rule built in the prototype survives unchanged and gains a fourth tier: thread opener → earliest live participant → the bound channel's human → unclaimed queue. Attached agents keep asking their own user, because when a person is right there it beats a ticket round-trip by minutes.

The reply path is a webhook. A human answers in Linear or Slack, the adapter turns that into a DECIDE, and the operator respawns whoever was waiting on it. The human never learns the bus exists — they answer a question on a ticket, which is what they were going to do anyway.

Inward — interjection and hold

Nothing so far lets a person steer a conversation that has not gone wrong. Two additions:

Steer

Comment into a live thread

A human message on an open thread is just a message — but in detached mode it is also a trigger, and the operator respawns participants with the steer already in their context.

Stop

Hold and resume

agora hold <thread> freezes spawning without closing the thread. It is both a cost brake and the "stop, I need to think about this" the prototype has no way to express.

Design tension worth naming

Every escalation that reaches a person is a success for correctness and a failure for autonomy. Tuning the hop cap up reduces interruptions and increases the chance two agents converge confidently on something wrong; tuning it down does the reverse. There is no setting that avoids the trade, so the number SHOULD be treated as a dial the team moves deliberately, per thread class, with the escalation rate as the signal.

§ 7

The adapter seam

“Public core, private Era adapters” only means anything if the seam is defined before the Era-shaped code is written. The core knows about threads, messages, leases, hops, and that a human is needed. It knows nothing about Linear, Slack, GitHub, Kubernetes, or Era.

// The entire Era-facing surface. Three interfaces.

interface WorkItemResolver {
  parse(threadId: string): WorkItem | null;    // thread://linear/ERA-8397
  owner(item: WorkItem): Principal | null;
  hopBudget(item: WorkItem): number;              // thread class → cap (§3)
}

interface EscalationChannel {
  resolve(thread: Thread): ChannelRef | null;
  notify(ref: ChannelRef, digest: Digest): Promise<Handle>;
  // replies arrive out-of-band and call core.decide()
}

interface Executor {
  spawn(turn: TurnSpec): Promise<TurnResult>;         // §3
  cancel(turnId: string): Promise<void>;
}
InterfacePublic defaultEra implementation
WorkItemResolverRepo and branch onlyLinear, GitHub
EscalationChannelWrites to stdout and the dashboard queueLinear comment, PR review, Slack
ExecutorLocal subprocessA service built on this library

The public defaults are not stubs — they make the core independently useful on one machine, which is the only honest test that the seam is real. A core that needs the Era adapters to do anything has the abstraction in name only.

What makes the standard real

A protocol nobody can test against is “whatever the reference CLI happens to do today”, which is where the prototype is now. Three things change that:

  • The envelope published as JSON Schema plus prose, versioned agora/1. Readers ignore unknown fields and refuse unknown major versions.
  • A conformance suite — an adversarial fake agent driving lease denial, hop cap, ownership assignment, stale refs, bad signatures, duplicate turn_id, and a mid-turn death. Passing it is the definition of interoperating.
  • The suite MUST exist before the second implementation, not after. Compatibility rules written retroactively are just a description of the first bug.
§ 8

Memory — how a fresh agent gets its position back

Withdrawn 2026-08-20 — kept for the record, do not build. Q9 was answered by measurement (docs/plans/q9-replay-cost.md): at real thread lengths replay is 1–6% of a turn under prompt caching, and the projection below would rewrite the prefix as it recompresses, which is precisely what defeats that caching. The section's one durable finding — positions and citations must never pass through a summariser — survives as a constraint on the protocol, not as an architecture.

“The thread is the agent's memory” (§1) quietly assumes replay is cheap. It is not, at real thread lengths — but the fix is not summarisation, and the evidence on that is unusually clear.

The finding that constrains everything below

Replacing verbatim history with LLM-extracted artifacts costs 15.9 points on LoCoMo (43.9% → 28.0%), and 77 points on constraint recall specifically (91.0% → 14.0%).1 Constraint recall is precisely our workload: who claimed what, and does it still stand.

So: positions, citations, disagreements and ratified decisions MUST NOT pass through a summariser. Not as a quality preference — as a correctness boundary.

A projection, not a summary

The distinction is the whole design. A summary is a paraphrase: unverifiable, undiffable, and it drifts a little more every time it is regenerated from itself. A projection is a deterministic transform of the log: recomputable, byte-comparable against a second run, and testable for equivalence. Every record in it points at a message id and quotes that message verbatim.

Because the bus is already an append-only log, this is the shape it wanted all along — the same event-sourcing move as bus.claims, applied to conversation state instead of lease state.

What the snapshot holds

Typed records, each carrying msg_id and a verbatim quote. Nothing paraphrased.

{
  "snapshot_at_seq": 312,
  "log_digest": "blake3:…",          // detects divergent replay

  "positions": [ { "agent", "proposition_quote", "asserted_msg",
                  "status": "open|conceded|withdrawn|superseded",
                  "status_msg" } ],       // the explicit speech act — never inferred

  "citations": [ { "path", "lines", "content_hash", "cited_by_msg",
                  "verified_at_head" } ],  // recomputed on every read

  "open_disagreements": [ { "topic_quote", "sides", "last_movement_msg" } ],

  "ratified": [ { "decision_quote", "ratified_by", "msg" } ],  // append-only, never GC'd

  "narrative": "…"   // the ONLY prose. Regenerated from the LOG every time,
                    // never from the previous narrative. That single rule
                    // is what defeats recursive summarisation drift.
}

What stays verbatim, always

  1. Every message in the tail.
  2. Every quoted proposition, decision and disagreement topic in the snapshot.
  3. Every citation's path, line range and content hash — never the file contents; re-read those at the hash.
  4. Every message anchoring an open disagreement, regardless of age, pinned into the prompt even if it precedes the snapshot.

That last rule is structural rather than semantic, and it is the direct answer to the documented failure of retrieval-based memory on this shape of history: you usually need the last fifty turns, not the fifty most similar ones. Pinning by argument structure gets that right where embedding similarity does not.

Already built, as it turns out

The prototype's pinned citations — path#L40-60 plus a content hash, recomputed on read and rendered [REF STALE] when the file has moved — are exactly the citation-integrity mechanism this design needs. A fresh agent sees that the evidence behind a position has rotted, instead of arguing against a file that no longer says what was quoted. Cheap, deterministic, no model in the path.

Concessions are read, never inferred

The closest published analogue to the snapshot's structure updates stance automatically from accumulated evidence weight, and its own stated limitation is that this misfires for participants whose position is stable or evidence-opposed.2 An agent conceding is a speech act in the log. status: conceded MUST be set only from an explicit CONCEDE event, never derived.

Prompt caching helps, but does not dissolve this

Cache reads cost 0.1× and writes 1.25–2×, so it is genuinely large — but it is a burst optimisation and our cost problem is chronic. Arguments have human-scale gaps: review cycles, CI runs, sleep. Most turns start cold regardless of TTL. Two consequences worth building around:

  • Hoist a shared prefix. System content renders before messages, so a per-agent system prompt above the history gives N agents N disjoint caches of the same thread. Inject identity below the shared prefix as a mid-conversation system message instead. Highest-leverage caching change available here.
  • Model the blend, not the read rate. A thread that re-snapshots every turn pays the write premium every turn and can end up more expensive than no caching at all. The “90% cheaper” framing quotes the read multiplier in isolation.

Prefix invalidators to audit: interpolated timestamps or UUIDs, non-deterministic JSON key order, per-agent ids above the history, conditional system sections, and any tool-set change at all — tools render at position zero. Verification is one field: if cache_read_input_tokens stays at zero across repeated same-prefix requests, something is silently invalidating.

When compression triggers

On token budget, not message count — forty one-liners and forty diff-dumps are different problems. Snapshot when the tail exceeds budget, and no open disagreement's anchor would fall out of it, and the previous turn has already published. Recompute in the idle window after a turn, never while a spawning agent waits. Writes are atomic and idempotent, keyed by snapshot_at_seq.

Measure before building any of this

Agents also read files, run tools and think. If replay turns out to be under ~10% of total turn cost at realistic thread lengths, the correct answer is prompt caching and nothing else, and every paragraph above is premature.

Validate with a shadow eval: run sampled turns twice — full replay versus snapshot-plus-tail — and diff the outcome. Falsifiers, any one of which kills the design as drawn: decision divergence above 2%; a single attribution error; a ratified decision disappearing; concession lag above one turn (which means stance is being inferred somewhere); or narrative drift detectable across three snapshots.

§ 9

Finding and joining the right thread

Observed, not hypothetical

Two agents working the same review on the running prototype each opened their own thread. One of them later closed its own with the message “Superseded by th-w5-consensus, where both agents' numbered positions and evidence are now recorded.”

They recovered — by hand, in prose, after spending turns on it. That recovery is the missing primitive, and the fact that a working agent invented it unprompted is good evidence it belongs in the protocol.

Two failures, and you cannot fix both by leaning one way

Fragmentation is what happened above: parallel threads on one subject, split evidence, an escalation digest that sees only half the argument. The obvious cure is to push agents toward existing threads.

Push too hard and you get conflation: unrelated work crammed into one thread, hop budget consumed by cross-talk, and a human asked to rule on a question tangled with two others. Conflation is the worse failure, because fragmentation is recoverable and a poisoned thread is not.

So a suggestion MUST be declinable. The design's job is to make convergence the low-effort path and divergence a deliberate, recorded act — not to remove the choice.

You describe an intent; you do not name a thread

The prototype lets an agent invent a slug and start talking, which is precisely how you get two of them. Opening becomes a two-step act instead, and the first step creates nothing:

$ agora open --title "CICD fold into N — settled or pending?" \
      --paths w5-infrastructure-project-review.md,docs/protocol.md

CANDIDATES (2)
  thread://linear/ERA-8397          strong   open · hop 3/20 · claude-a, codex-a
    matched: work item derived from branch · 2 of 2 paths overlap
    last:    "ERA-8397 is a pending disposition, not a ruling…"

  th-a0-execution                   weak     open · hop 2/20 · claude-a
    matched: 1 of 2 paths overlap
    last:    "A0 executed and logged. Highlights: all 4 status flips…"

# join it…
$ agora open --join thread://linear/ERA-8397

# …or decline, with a reason that goes on the record
$ agora open --title "…" --paths … \
      --decline thread://linear/ERA-8397 \
      --reason "That thread is settling the ruling. This is about the doc's
                rendering of it, which is orthogonal and should not consume
                its hop budget."

Ranking, and why evidence travels with the score

Candidates are ranked deterministic-first, and each carries why it matched. A bare similarity score is unadjudicable — the agent is being asked to make a judgement, so it needs the grounds, not a number.

TierSignalDefault
ExactSame work item — the derived thread id is arithmetic, not a guessJoin. Declining requires a reason; duplicating a work-item thread is almost always wrong.
StrongOpen thread whose descriptor paths overlap the intent's pathsSuggest, with the overlap enumerated.
WeakTitle or tag similarity, no path overlapSuggest, clearly marked weak. Silence is a fine response.

Matching reads the compacted bus.index descriptor — one record per thread, so a client can pull the whole index and rank locally. No operator in the path, for the same reason discovery does not need one: an agent most needs to know what else is in flight precisely when the control plane is unwell.

Declines are recorded

A declined suggestion MUST be published as a DIVERGE record on bus.index, carrying the rejected candidate and the stated reason. This is not bureaucracy — it buys three things:

  • Duplicate threads stop being silent. A bad call is visible in review instead of surfacing three days later as a superseded thread.
  • The operator gets its only real signal for whether matching is tuned right. Repeated declines against the same candidate mean the matcher is wrong, not the agents.
  • The next agent to consider the same split reads the prior reasoning rather than re-deriving it.

SUPERSEDE — convergence after the fact

Matching will miss. Two agents can start minutes apart on work that only turns out to be the same subject at hop 3. SUPERSEDE --into <thread> is terminal on the source thread and:

  • links rather than copies — the messages stay where they were published, and catchup on the target follows the pointer, so nothing is duplicated and no ordering is invented;
  • carries the source's positions and citations into the target's projection (§8), so an argument does not lose evidence by being merged;
  • refuses if the target is terminal — you cannot merge into a settled thread, only into a live one.

Hop budgets do not sum. The target keeps its own, because merging two half-spent arguments into one exhausted thread would escalate a conversation that has barely started.

The operator can also point

Everything above is pull. The operator additionally SHOULD watch for open threads with overlapping paths and post a RELATED marker into both. It suggests; it never merges. Merging is a judgement about subject matter, and the operator has no view of subject matter — only of paths.

Anti-pattern

Auto-joining an agent to the best match without adjudication. It converts a visible, recoverable failure — two threads — into an invisible, unrecoverable one: a single thread whose hop budget is consumed by two arguments, escalating to a human with a digest that makes sense for neither.
